# 학습 노트

처음 만나는 백엔드 개념을 만난 날짜순으로 적는다. 꾸미지 않는다.

| 날짜 | 만난 문제 | 이름 | Nest에서 | 프론트로 치면 |
|---|---|---|---|---|
| 2026-09-10 | `GET /health` 하나를 만드는 데 파일이 셋 필요했다 | Controller · Service · Module | `@Controller`가 URL을 받고, `@Injectable` Service가 일을 하고, `@Module`이 둘을 묶는다 | 라우트 컴포넌트 · 그 안에서 부르는 훅/함수 · 앱 루트의 Provider 트리 |
| 2026-09-10 | Controller가 Service를 `new` 하지 않는데 쓸 수 있다 | 의존성 주입(DI) | 생성자 파라미터 타입을 보고 Nest가 인스턴스를 넣어 준다 | `useContext` — 값을 직접 만들지 않고 위에서 내려받는다 |
| 2026-09-11 | GBIS JSON을 `as` 단언으로 쓰면 틀린 모양이 DB까지 흘러간다 | 경계에서 파싱 | `src/domain/gbis/parse.ts`에서 필드 검사 + KST→UTC + 코드→이름, 틀리면 즉시 throw | zod를 제출 지점 한 곳에서만 |
| 2026-09-11 | "내 코드가 맞나"가 아니라 "GBIS와의 약속이 아직 유효한가"를 검사해야 한다 | 계약 테스트 | 녹화된 실제 응답(fixture)을 파서에 넣는 spec 17개 | MSW 핸들러의 반대 방향 |
| 2026-09-11 | 폴러가 GBIS 응답을 영원히 기다리면 틱이 쌓여 서버가 죽는다 | 타임아웃 | `AbortSignal.timeout(5000)`을 모든 바깥 호출에 | `AbortController`, 이유만 다름 |
| 2026-09-11 | 한 번 실패로 60초 구멍이 생긴다. 그런데 4xx·한도초과는 다시 해도 같다 | 재시도 · 지수 백오프 | 타임아웃·5xx만 500→1000→2000ms로 3번 | React Query `retry` 옵션의 속 |
| 2026-09-11 | 문서 보고 `crowded: 'Y'/'N'`으로 잡았는데 실제는 숫자 1~4 혼잡도였다 | 계약 테스트의 존재 이유 | 녹화 fixture로 spec 추가, 타입을 `crowding` 4단계로 수정 | 디자인 시안만 믿고 만든 컴포넌트가 실데이터 붙이니 깨지는 것 |
| 2026-09-12 | Neon에도 내 맥에도 같은 표 모양이 필요한데 DB는 상태를 가진다 | 마이그레이션 | `migrations/NNN_*.sql` + `schema_migration` 이력 표, 파일 = 트랜잭션 | git. 단 되돌리기 없음 |
| 2026-09-12 | 정류소 이름·좌표가 노선마다 중복 저장된다 | 정규화 · PK/FK | `station`과 `route_station` 분리, FK로 없는 노선 거부 | 엔티티 map + id 배열 |
| 2026-09-12 | 형상 1,512행을 넣는데 Neon 왕복 1,512번 | 왕복 횟수 | `unnest` 배열 INSERT 한 번 | 요청 하나로 묶기 |
| 2026-09-27 | GBIS가 70초 걸리면 `setInterval` 다음 틱이 앞 폴 위에 올라탄다 | 재진입 방지 | 끝나면-다음-예약 + `inFlight` 플래그. 가짜 타이머 테스트로 동시 실행 최대 1 고정 | `isLoading` 버튼 가드 |
| 2026-09-27 | 관측 표는 하루 수천 행씩 자라는데 "이 노선 이 기간"을 어떻게 찾나 | 인덱스 | `(route_id, observed_at)` 인덱스. UNIQUE 인덱스는 plate_no가 가운데라 기간 검색엔 못 탐 | 배열 `find` vs `Map` |
| 2026-09-27 | 폴러가 어떤 이유로든 죽으면 관측이 조용히 끊긴다 | 실패 격리 | GBIS 실패는 `failed`로 기록, DB 실패는 로그 후 다음 바퀴. `/health`에 마지막 폴 노출 | 에러 바운더리 |
| 2026-09-27 | GBIS `queryTime`이 우리 시계보다 53초 앞선다. 회차 중엔 차량이 목록에서 사라진다 | (아직 이름 없음 — 관측 중) | `poll_run.finished_at`과 `observed_at` 차이를 며칠 보기 | 데이터가 문서와 다를 때 먼저 기록 |
