# 00. 왜 서버가 필요한가 — 기획서를 쉬운 말로

> 기획서 원문: `claude/Waiting-7000-Bus 고도화 기획서` v1.3. 이 글은 그걸 백엔드를 모르는 사람이 읽을 수 있게 다시 쓴 것이다.

## 진짜 문제 (2026-09-11, 사용자 본인의 말)

> 매번 버스를 타는데 언제쯤 올지 가늠이 안 된다. 시간표엔 출발 정류소 시각만 있고 정류장별 시각이 없어서, 매번 "이때쯤 나가면 되겠다" 하고 감으로 나간다.

그래서 이 프로젝트가 관측을 쌓는 이유는 결국 하나다. **시간표에 없는 "내 정류장 도착 시각"을 관측으로 만들어 내는 것.** 출발 시각 + 구간별 보통 소요시간(p50/p90) = 정류장별 시각표. GBIS 도착 API는 버스가 이미 출발한 뒤에만 답하지만, 이건 집에서 나가기 전에 쓰는 것이다.

지도 위 마커는 그다음이다. 기능 순서는 이 문장을 기준으로 다시 정한다.

## 지금 앱은 서버가 없다

현재 Waiting-7000-Bus는 **정적 사이트**다. 시간표 JSON 3개(`dayBus.json` 등)가 빌드에 포함되고, Vercel이 그 파일들을 그대로 내려준다. 브라우저가 전부 계산한다. 서버가 하는 일은 "파일 주기"뿐이다.

이 구조로 못 하는 것이 하나 있다. **"지금 버스가 어디 있나"** 다. 그건 경기도 버스 API(GBIS)에 물어봐야 하는데, 브라우저에서 직접 물어보면 세 가지가 깨진다.

| 브라우저가 직접 부르면 | 왜 안 되나 |
|---|---|
| API 키가 노출된다 | JS 번들에 들어가면 누구나 꺼내 쓴다. 키는 서버에만 있어야 한다 |
| 사용자 수만큼 호출이 늘어난다 | 하루 1,000건 한도. 10명이 30초마다 부르면 오전에 끝난다 |
| 기록이 안 남는다 | "시간표는 몇 분 틀리나"를 알려면 관측을 **쌓아야** 한다. 브라우저는 쌓을 곳이 없다 |
| 애초에 막힌다 (CORS) | 공공데이터포털 API는 브라우저의 교차 출처 요청을 허용하는 헤더를 안 보낸다. `curl`은 되고 `fetch`는 안 된다 |

연산(거리 계산 등)을 서버에서 하기 위해서가 **아니다.** 그건 브라우저도 한다. 서버는 "계산하는 곳"이 아니라 **키를 쥐고, 한 번만 묻고, 기억하는 곳**이다.

그래서 **가운데에 하나** 둔다. GBIS에는 우리 서버 하나만 60초마다 묻고, 브라우저들은 우리 서버에 묻는다. 이것이 "백엔드"의 전부다. 나머지는 이걸 안 죽게, 안 틀리게 만드는 일이다.

```
브라우저 ×N  ──HTTP──▶  우리 서버 (NestJS)  ──60초마다 1번──▶  GBIS API
                              │
                              ▼
                        PostgreSQL (기록)
```

## 조각별로: 이게 왜 있나

### NestJS — 서버를 만드는 틀
Node.js로 HTTP 요청을 받는 프로그램을 만드는 프레임워크. React가 "화면을 컴포넌트로 쪼개는 틀"이라면 Nest는 "요청 처리를 Controller·Service·Module로 쪼개는 틀"이다. 코드잇에서 쓴 Express보다 구조를 더 강제한다.
왜 Nest인가: 네이버랩스 JD 필수요건. 그리고 강제된 구조가 처음 배울 땐 오히려 길잡이가 된다.

### PostgreSQL — 기록을 남기는 곳
관계형 데이터베이스(RDB). 표(table)에 행(row)을 쌓는다. 프론트로 치면 Zustand 스토어인데, **프로세스가 죽어도 남고, 여러 서버가 같이 보고, 수백만 행을 빨리 찾을 수 있는** 스토어. 이 프로젝트에선 60초마다 관측 한 줄씩 쌓는다(`vehicle_observation`).

### pg + SQL 직접 — DB에 말 거는 방식
DB에 말을 걸 땐 SQL이라는 언어를 쓴다. Prisma는 SQL을 감춰 주고(코드잇 때), Kysely는 TS 메서드 체인으로 SQL을 만들어 준다. 이번엔 둘 다 안 쓰고 **`pg` 드라이버에 SQL 문자열을 그대로** 쓴다(2026-09-11 결정, 기획서 ADR-003 수정). 인덱스·트랜잭션·`EXPLAIN`을 보려는 게 목적이라 SQL이 그대로 보이는 게 가장 직접적이다. 대가는 컬럼명 오타를 실행해 봐야 안다는 것 하나. 그 불편이 실제로 생기면 그때 Kysely를 얹는다.

### 마이그레이션 — 표 모양을 바꾸는 기록
표를 만들고 컬럼을 더하는 SQL 파일을 번호 붙여 저장소에 둔다(`001_init.sql`, `002_...`). git이 코드 변경 이력이면, 마이그레이션은 **DB 모양의 변경 이력**이다. 새 컴퓨터에서 순서대로 돌리면 같은 DB가 나온다.

### 폴러(Poller) — 60초마다 GBIS에 묻는 놈
서버 안에서 혼자 도는 타이머. 프론트의 `setInterval`과 같은데, 서버는 24시간 켜져 있으니 진짜 문제가 여기서 터진다: 응답이 늦어 다음 틱과 겹치면? 같은 걸 두 번 저장하면? 서버가 재시작하면? — 6단계에서 하나씩.

### SSE — 서버가 브라우저에 밀어주기
보통 HTTP는 브라우저가 물어야 답한다. SSE(Server-Sent Events)는 연결을 열어 두고 서버가 새 데이터가 생길 때 밀어준다. `EventSource`라는 브라우저 API로 받는다. WebSocket과 달리 한 방향이고 재연결이 내장돼 있어 이 용도(30~60초마다 한 번)엔 충분하다.

### Render · Neon — 공짜로 켜 두는 곳
- **Render**: 우리 Nest 서버를 돌려 주는 곳. Vercel이 정적 파일 호스팅이면 Render는 "계속 도는 프로세스" 호스팅. 무료 티어는 15분 요청이 없으면 잠든다 → cron-job.org가 10분마다 `/health`를 찔러 깨운다.
- **Neon**: PostgreSQL을 돌려 주는 곳. 우리는 접속 주소만 받는다.

### 3층 구조 — domain · application · infra
`src/` 안을 이렇게 나눈다.

| 층 | 뭐가 들어가나 | 규칙 | 프론트로 치면 |
|---|---|---|---|
| `domain/` | 순수 계산. 위치 추정·이상 감지·예산 정책 | **Nest import 0개**. `fetch`도 DB도 없음 | chart-lib에서 히트 판정을 순수 함수로 뺀 것 |
| `application/` | 유스케이스. "폴 한 번" = fetch → 파싱 → 저장 → 이상감지 | domain을 조합. Nest import 0개 | 커스텀 훅 (여러 순수 함수를 순서대로 부름) |
| `infra/` | Nest·pg·HTTP. 바깥 세상과 닿는 곳 | 여기만 프레임워크 | 컴포넌트·API 클라이언트 |

왜 이렇게까지 하나: `domain/`과 `application/`이 Nest 없이 테스트되면, 나중에 (1) 그 폴더를 npm 패키지로 빼서 프론트와 공유할 수 있고 (2) `infra/`만 FastAPI나 Spring으로 다시 써서 "프레임워크에 구애받지 않는다"를 물증으로 만들 수 있다.

## 이 프로젝트가 던질 문제 9개 (기획서 §12-2)

기능을 더 안 만들어도 만나게 되는 것들. **지금 외우지 않는다.** 만나면 그 단계 수업 노트에 쓴다.

| # | 터지는 모양 | 이름 | 단계 |
|---|---|---|---|
| 1 | GBIS 응답이 늦어 다음 폴과 겹친다 | 재진입 방지 | 6 |
| 2 | 재시도 때문에 같은 관측이 두 번 저장된다 | 멱등성 | 6 |
| 3 | 관측은 저장됐는데 이상징후 저장이 실패한다 | 트랜잭션 | 6 |
| 4 | GBIS가 타임아웃·500을 낸다 | 재시도·서킷브레이커 | 4 |
| 5 | 운행시간 판정이 서버 UTC에서 틀린다 | 시간대 | 7 |
| 6 | 스냅샷 요청마다 DB를 읽는다 | 캐시 | 8 |
| 7 | 클라이언트 100명이어도 폴은 1회 | 팬아웃 | 8 |
| 8 | 관측이 무한히 쌓인다 | 보존 정책·롤업 | 나중 |
| 9 | 폴러가 죽었는지 아무도 모른다 | 관측성 | 나중 |

## 단계 순서

```
0 스캐폴드 ✅ → 1 /health ✅ → 2 fixture 녹화 → 3 파서 + 계약 테스트 → 4 GBIS 클라이언트
→ 5 Neon + Kysely + 마이그레이션 → 6 폴러 → 7 Render 배포 → 8 스냅샷 + SSE
```
