# 용어 사전

찾아볼 때만 쓴다. 순서대로 읽지 않는다.
각 항목: **한 줄 뜻 · 프론트로 치면 · 만나는 단계**. "아직 안 만남"은 그 단계에서 채운다.

## 서버 기본

- **API 서버** — HTTP 요청을 받아 JSON을 돌려주는 프로그램. · 프론트로 치면 지금까지 `fetch`로 부르던 상대. · 1단계 ✅
- **엔드포인트 / 라우트** — `GET /health`처럼 메서드+경로 한 쌍. · React Router의 `path` 하나. · 1단계 ✅
- **HTTP 메서드** — GET(읽기)·POST(만들기)·PUT/PATCH(고치기)·DELETE. 이 프로젝트는 거의 GET만. · 1단계 ✅
- **상태 코드** — 200 성공 · 404 경로 없음 · 500 서버 에러 · 503 준비 안 됨. · 1단계 ✅
- **포트** — 한 컴퓨터에서 프로그램을 구분하는 번호. Vite는 5173, Nest는 3000. · 1단계 ✅
- **환경변수 / `.env`** — 코드 밖에서 주입하는 설정값. 비밀(API 키)은 반드시 여기. Node 22는 `node --env-file=.env`로 직접 읽는다. · Vite의 `import.meta.env`와 같은 개념, 서버에선 `process.env`. · 4단계 ✅
- **HTTP 4xx vs 5xx** — 4xx는 내 요청이 틀림(다시 보내도 같음), 5xx는 상대 서버 문제(잠시 뒤 될 수 있음). 재시도 여부를 가르는 기준. · 4단계 ✅
- **CORS** — 브라우저가 다른 출처(도메인)로 보내는 요청을 서버가 허용 헤더로 열어 줘야 하는 규칙. 공공 API는 대개 안 열어 줘서 브라우저 직접 호출이 막힌다. 서버끼리(`curl`, Node `fetch`)는 해당 없음. · 4단계
- **`curl`** — 터미널에서 HTTP 요청을 보내는 도구. · 브라우저 주소창을 명령줄로. · 1단계 ✅

## NestJS

- **Controller / Service / Module** — [01 노트](01-health-endpoint.md) 참조. · 1단계 ✅
- **데코레이터 `@Get()` 등** — 클래스·메서드에 붙이는 라벨. Nest가 실행 시 읽는다. · 1단계 ✅
- **의존성 주입(DI)** — `new` 없이 생성자 타입만 적으면 Nest가 인스턴스를 넣어 줌. · `useContext`. · 1단계 ✅
- **`@nestjs/schedule`** — 서버 안 타이머(크론). · `setInterval`이지만 24시간 돎. · 6단계
- **가드/파이프/인터셉터** — 요청 전후에 끼어드는 미들웨어. 이 프로젝트에선 거의 안 씀. · 아직 안 만남

## 테스트

- **단위 테스트** — 함수 하나를 직접 호출. · Vitest, 이미 앎. · 1단계 ✅
- **e2e 테스트** — 진짜 HTTP 요청을 보내 검사. `supertest`. · 1단계 ✅
- **fixture** — 실제 API 응답을 파일로 녹화한 것. `fixtures/gbis/*.json`. · MSW 핸들러에 넣던 그 JSON. · 3단계 ✅ (위치 fixture는 2단계에서 녹화)
- **계약 테스트** — fixture를 파서에 넣어 "우리가 기대하는 모양"이 나오는지. API가 바뀌면 여기서 먼저 깨진다. · [03 노트](03-parser-contract-test.md) · 3단계 ✅

## 구조

- **경계에서 파싱** — 바깥(API·DB·폼) 데이터가 들어오는 한 지점에서 모양을 검사하고 우리 타입으로 바꾼다. 그 뒤는 우리 타입만 돈다. · zod를 제출 지점 한 곳에서만 쓰는 것. · [03 노트](03-parser-contract-test.md) · 3단계 ✅

- **domain / application / infra** — [00 노트](00-why-a-server.md) 3층 구조 참조. `src/domain/gbis/`가 첫 domain 코드. · 3단계 ✅
- **포트(port) / 어댑터** — domain이 "이런 모양의 것이 필요해"라고 인터페이스만 선언(port), infra가 진짜 구현(adapter). `domain/ports.ts`의 `GbisPort` ↔ `infra/gbis/HttpGbisClient`. · props로 콜백만 받고 구현은 부모가 주는 것. · 4단계 (5단계에서 DB로 다시)
- **유스케이스** — "폴 한 번"처럼 한 문장으로 말할 수 있는 일 단위. · 커스텀 훅. · 6단계

## 외부 API 호출

- **타임아웃** — 응답을 N초까지만 기다리고 포기. 서버의 모든 바깥 호출에 필수. · `AbortController`. · [04 노트](04-gbis-client-timeout-retry.md) · 4단계 ✅
- **재시도 / 지수 백오프** — 일시적 실패(타임아웃·5xx)만 500ms·1s·2s 간격으로 다시. 4xx와 한도 초과는 안 함. · React Query `retry`. · 4단계 ✅
- **서킷브레이커** — 연속 실패가 쌓이면 잠시 아예 안 부름. · 4단계

## 데이터베이스

- **PostgreSQL** — 관계형 DB. 표에 행을 쌓음. · 죽어도 남는 Zustand 스토어. · 5단계
- **SQL** — DB에 말 거는 언어. `SELECT … FROM … WHERE …`. · 5단계
- **`pg`** — Node용 PostgreSQL 드라이버. `pool.query('SELECT … WHERE id = $1', [id])`처럼 SQL 문자열 + 파라미터 배열. 이 프로젝트의 선택. · `fetch`에 해당하는 DB 쪽 최소 도구. · 5단계
- **파라미터 바인딩 `$1`** — 값을 SQL 문자열에 끼워 넣지 않고 따로 넘기는 것. SQL 인젝션을 막는 방식. · 5단계
- **ORM / 쿼리 빌더** — Prisma(SQL을 감춤) / Kysely(TS로 SQL을 만듦). 둘 다 안 쓰기로 함(2026-09-11). 컬럼명 오타가 불편해지면 그때 Kysely 고려. · 5단계
- **마이그레이션** — 표 모양 변경을 번호 붙인 SQL 파일로 기록. · DB의 git. · 5단계
- **PK / FK** — 행을 유일하게 찾는 키 / 다른 표를 가리키는 키. · 5단계
- **인덱스** — 특정 컬럼으로 빨리 찾기 위한 보조 구조. 없으면 전부 훑는다. · 5단계
- **`EXPLAIN`** — 이 쿼리를 DB가 어떻게 실행할지 보여 주는 명령. 인덱스를 타는지 여기서 본다. · 5단계
- **`timestamptz`** — 시간대가 붙은 시각 타입. 항상 UTC로 저장. · 5단계
- **트랜잭션** — 여러 쓰기를 "전부 성공 or 전부 취소"로 묶기. · 6단계
- **멱등성** — 같은 요청을 두 번 해도 결과가 한 번과 같음. `UNIQUE` + `ON CONFLICT DO NOTHING`. · 6단계
- **append-only** — 행을 고치지 않고 늘 새로 추가. 이력이 남아 리플레이가 됨. · 5단계

## 폴링·실시간

- **폴링** — 주기적으로 물어보기. · `setInterval` + `fetch`. · 6단계
- **폴링 예산 / 일일 한도** — 개발계정 키는 하루 1,000건. 넘으면 밴이 아니라 에러 코드 22가 오고 자정에 초기화. 60초×24시간=1,440이라 출퇴근 60초·그 외 120초·새벽 중단으로 ≈800에 맞춘다. 서버가 있어야 사용자 수와 무관하게 이 예산이 고정된다. · 6단계
- **재진입 방지** — 앞 실행이 안 끝났으면 다음 틱을 건너뜀. · `isLoading` 가드. · 6단계
- **SSE** — 서버가 브라우저로 밀어주는 단방향 연결. `EventSource`. · 8단계
- **팬아웃** — 폴은 1회, 구독자 N명에게 뿌리기. RxJS `Subject`. · 8단계
- **캐시 / stale-while-revalidate** — 요청마다 DB 대신 메모리의 최신값. · `useMemo` · 8단계

## 운영

- **배포** — 코드를 남의 컴퓨터에서 돌리는 것. · Vercel에 올린 것과 같은데 "계속 도는 프로세스". · 7단계
- **Render / Neon** — 서버 호스팅 / Postgres 호스팅. 무료. · 7단계
- **슬립 / keep-alive** — 무료 서버는 15분 놀면 잠듦. 10분마다 `/health`를 찔러 깨움. · 7단계
- **UTC / KST** — 서버는 UTC, 한국은 +9. 저장은 UTC, 판정·표시만 KST. · 7단계
- **헬스체크** — `/health`. 호스팅이 "살아 있나" 확인하는 용도. 나중엔 "마지막 폴 시각"도 넣는다. · 1단계 ✅
- **관측성** — 로그·메트릭으로 "지금 뭐가 어떻게 되고 있나"를 알 수 있는 정도. · 나중
- **ADR** — 아키텍처 결정 기록. "왜 이걸 골랐나"를 한 장씩. `docs/adr/`. · 나중
